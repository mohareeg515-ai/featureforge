# Data dictionary

## Provenance

| Dataset | Origin | Real or synthetic |
|---|---|---|
| Transactions | **Preferred:** UCI *Online Retail* — https://archive.ics.uci.edu/dataset/352/online+retail . Otherwise the seeded synthetic generator `ingestion/synthetic.py` | Real only when `FF_SOURCE_KIND=retail_file`; the default is **synthetic** and every row carries `is_synthetic = true` |
| Customer events (`session_start`, `add_to_cart`) | Generated by `derive_events` (seeded, consistent with the orders) | **Always synthetic**: the real dataset has no clickstream |

**Verification status.** The execution environment used to build this repository could not
reach archive.ics.uci.edu (outbound network is allow-listed), so the dataset's availability,
schema and licence were **not verified here**. From the UCI documentation as I know it: ~541k
rows, 8 columns, Dec 2010 - Dec 2011, a UK-based online retailer, listed as CC BY 4.0 (to be
re-checked on the page before redistribution). The real-data path is exercised in tests
only with a small hand-written CSV in the same column layout, never with the real file.
The download helper (`featureforge download-retail`) records the source URL and SHA-256 in
`provenance.json`. Raw data is git-ignored; do not commit it.

Known limitations of the real dataset: no customer attributes, no clickstream, ~25% of rows
without `CustomerID`, cancellations (invoice numbers starting with `C`), non-product stock
codes (e.g. `POST`, `D`), exact duplicate rows, no availability/ingestion timestamps.

## Raw transactions (`raw/source=transactions`)

Original Online Retail names are preserved.

| Column | Type | Notes |
|---|---|---|
| InvoiceNo, StockCode, Description, Country | string | as in source |
| Quantity | int64 | negative for cancellations |
| InvoiceDate | datetime(us) | event time, naive UTC |
| UnitPrice | float64 | |
| CustomerID | string, nullable | raw form, e.g. `17850.0` |
| record_id | string | `invoice|stock|customer|invoice_ts|line_seq`; version key |
| line_seq | int64 | occurrence index of identical (invoice, stock, customer, ts) |
| available_at | datetime(us) | when the platform could first see the record |
| is_synthetic, source_name | bool, string | provenance flags |
| ingestion_date | date | partition value (added at ingestion) |

Each partition has `_meta.json`: source info, row counts, min/max event time, coverage window
`(available_after, available_up_to]`, content fingerprint, Parquet SHA-256, schema, version.

## Normalized transactions (`normalized/transactions.parquet`)

`record_id, invoice_no, stock_code, description, quantity, unit_price, invoice_ts, available_at,
customer_id (standardized), country, is_synthetic, source_name, ingestion_date`.

Cleaning rules (rows failing any rule go to `rejected/` with `reject_reason`, in priority order):
`missing_customer_id`, `missing_timestamp`, `missing_quantity_or_price`, `cancellation`,
`non_positive_quantity`, `non_positive_price`, `non_product_stock_code` (regex
`FF_PRODUCT_CODE_REGEX`), then `exact_duplicate`. Customer ids are trimmed; `17850.0` becomes
`17850`; blanks/`nan` become NULL. Record *versions* (same `record_id`, different
`available_at`) are retained.

## Customer events

`event_id, customer_id, event_type ∈ {session_start, add_to_cart}, event_ts, available_at,
is_synthetic, source_name, ingestion_date`. Normalization rejects missing customer/timestamp,
unknown types and duplicates.

## Feature snapshots (`feature_store/customer_features`)

`customer_id`, `snapshot_ts`, then the 12 features in `feature_definitions.md`. Partition key
`snapshot_date` (directory name). `_metadata.json`: `batch_id`, `input_fingerprint`,
`transformation_version`, `row_count`, `schema`, `parquet_sha256`, `published_at`,
`publish_count`, `run_id`.

## Run registry (`metadata/runs.jsonl`)

One JSON object per run: `run_id, snapshot_date, status (success|skipped_duplicate|failed),
batch_id, started_at, finished_at, duration_s, tasks[{name,status,duration_s}], rows{...},
validation{checks,warnings,critical}, freshness_hours, published, quality_report, error{category,
type,message}, orchestrator`.
